# Reading generation

Videos and podcasts default to **full transcript, one generation**. Settings →
LLM Configuration → Summary generation also offers **Segmented generation**.
The account preference is `summary_generation_mode` (`single` or `segmented`);
engine constructors and factories accept `generation_mode` for CLI/test use.
Existing notes are not regenerated by a settings change.
Bare custom API hosts normalize to `/v1`; existing `/v1` suffixes and other
explicit API path prefixes are preserved.

## Pipeline

1. Validate/reuse the complete saved transcript. Add playback anchors only when
   the timed segments account for all source text; otherwise retain the raw
   text without inventing times. Hash the source and assign stable line IDs.
2. In `single` mode submit every source line in one generation request. Do not
   infer that a long recording needs partitioning from its duration or character
   count. A context-capacity or output-limit error fails explicitly and keeps the
   previous saved result. A normal provider stop is not sufficient: for sources
   of at least 12,000 characters, reject a draft whose evidence never reaches
   the latter half before caching or review. This narrow prefix-truncation guard
   is not a claim of semantic completeness and does not reject skipped credits.
   There is no implicit segmented fallback.
3. In `segmented` mode partition source ownership without dropping whitespace or
   unmatched tails. Each request owns its primary lines, with adjacent context
   to resolve incomplete sentences. A failed part retains its original source
   with a warning; authentication/configuration failures stop the job. Local
   extraction cannot declare a question unanswered in the whole recording.
4. Both modes produce chapters and paragraphs with **continuous source ranges**.
   Validate every endpoint, order and owned line. Preserve original quotes from
   one continuous range in each podcast evidence field, with a matching playback
   time; never splice nonadjacent excerpts into one verbatim quotation. Raw
   fallback blocks mark gaps explicitly. The model never supplies quotes or
   media timestamps. Invalid prose evidence fails generation rather than
   silently receiving manufactured references.
5. Independently review the full source in single mode, or bounded source batches
   in segmented mode, against the **global draft**,
   including later answers and already accepted missing-material additions.
   Review calls verify coverage; they do not regenerate the entire note. Add
   only missing material with valid source ranges. Incomplete receipts,
   unsupported claims or unavailable reviews produce an unverified notice;
   specifically identified unsupported paragraphs fall back to their original
   source ranges, and an unsupported opening is omitted. Their generated wording
   stays in the model checkpoint, not in the reading body.
   Model receipts are not proof of semantic completeness. Do not append another
   set of section conclusions. Exact duplicates with identical evidence are
   removed; semantic duplication is not inferred from a lexical score.
   If the provider explicitly rejects a whole-source **review** for context
   capacity (the draft adds input), partition only that review into bounded
   batches and record `review_capacity_fallback`. Generation remains a single
   whole-source request; generic failures do not trigger this review fallback.
6. Resolve screenshot time from a source ID **inside that paragraph's evidence**.
   Reject unknown/outside references, absent/out-of-range/nonchronological times
   and adjacent duplicate candidates. Keep the paragraph; skip the bad picture
   and show a provenance notice. Playback links in both video and podcast output
   also reject source times outside the known duration. Pixel correctness and visual relevance still
   require the media pipeline; transcript references alone cannot prove them.
   When the model omits the optional picture field, a chapter can use the first
   genuine timed line inside its first paragraph's evidence as its screenshot
   anchor. Diagnostics label this `chapter_source_anchor`. An explicitly invalid
   model reference is skipped rather than silently replaced with a nearby time.
7. Render the existing Markdown/summary format, extract frames through the
   existing media pipeline, then use the existing completion/version transaction.
   Cancellation, failures and retries retain the existing saved note. Raw model
   JSON is never streamed into the reader preview.

“One generation” means one whole-source drafting call. Independent coverage
reviews are additional model calls. Segmented mode additionally synthesizes one
short global opening when requested. The reading budget is shared across source
parts and remains advisory: essential steps, numerical scope and conditions take
priority over a word target.

## Independent coverage checklist

After the existing grounding review, both modes run the same draft-blind
inventory stage. Each bounded source batch is sent **without the draft**, with
short boundary context. All inventories finish before any checklist matching.
Items distinguish claims, experiments (manipulation and outcome), counterexamples,
conditions, disagreements and procedures. Each has validated source ranges;
receipts must include every owned source line. Boundary context does not confer
ownership and must not become a false claim that the whole source leaves a
question unanswered.

Matching compares small item batches with the whole evolving draft, including
later answers and the opening. Each item must be returned exactly once as
`covered`, `partial`, `missing` or `contradicted`. Covered items require supporting paragraph IDs and semantic agreement. Internal
receipts do not copy quotations; paraphrase and merged explanations are accepted. Topic similarity alone is
insufficient; raw source fallback is not certified as verified prose. This is
still a model judgment, not proof that the inventory found every important fact.
Inventory wording is not a word-for-word output requirement: incidental places,
dates, pets, metaphors and repeated examples do not create gaps unless they change
an argument, evidence or condition. Experimental setup/results, mechanisms,
meaningful numerical scope, attribution, uncertainty and objections still must
survive. Published source quotations still come directly from validated source ranges.

For missing/partial items, one local repair attempt proposes only absent meaning.
It does not rewrite existing paragraphs. Before adding it, a separate matching
call sees the original evidence and candidate draft. Each accepted paragraph must be used in complete coverage receipts with passing
grounding and nonduplication judgments. Unrelated unresolved items do not block
a valid local repair. Unchecked or failed candidates are discarded; support
depending on a rejected paragraph cannot certify a surviving half-repair.
Each proposed paragraph is also presented separately, with the full draft still
available for context and duplicate checks. The matcher must acknowledge every
proposed paragraph ID before its receipts can be accepted. This prevents a check
that silently ignores appended candidates from certifying the repair; the
acknowledgment alone is never sufficient without grounded, nonduplicate support.
Previously covered items may not regress. The original prose is retained. A contradiction remains explicit;
appending its opposite is not treated as a repair. Later batches see accepted
repairs, so they can recognize already restored meaning. After this pass, only
remaining partial, missing or unverified items receive one bounded recovery
pass against the final draft. This reuses the source inventory and retains item
IDs; it never regenerates the whole note. A later accepted addition may already
resolve an earlier item. Contradictions are not repaired by appending opposites.
The same independent grounding, novelty and acceptance rules apply in recovery;
there is no unbounded repair loop. Initial unresolved/failure counts and the
recovery-round count remain in diagnostics even when recovery succeeds.
Before any missing/partial item can trigger prose repair, a source-only check
verifies that checklist claim without seeing the summary. It can correct a
demonstrably invented condition, attribution
or causal claim, with a reason and source ranges constrained to that item's source
and short adjacent context. True conditions cannot be dropped to make coverage
easier. Corrected items are rematched before deciding whether repair is needed.
The same source-only check can classify a claim or example as `context_only`
with an explicit compression reason when it is incidental background or an
interchangeable illustration. Protected kinds (experiments, conditions, objections,
counterexamples and procedures) remain required. Context-only items are counted
separately from covered items; uncertainty defaults to required. This is a model
judgment, not a numeric accuracy score.
If source validation fails, that batch cannot propose new prose. Correction IDs
and failed source-validation batches are recorded. A corrected checklist does
not certify the draft automatically.
The final renderer orders additions by their real source evidence and applies
the existing media/time gates. Additions within an existing chapter's source
span inherit that chapter heading, avoiding alternating duplicate headings.
Prose order, paragraph IDs and evidence remain unchanged; uncovered source spans
can retain a new chapter, and later chronological revisits stay separate.

Invalid inventories, incomplete match receipts, unavailable providers and failed
repair checks remain unverified. Cancellation propagates. Terminal configuration
errors stop further checklist calls. Inventory, matching and repair responses
are validated before checkpointing; completed calls can be reused on retry.
Malformed schema/evidence responses get one bounded retry with validation feedback.
Internal matching validates actual paragraph IDs rather than generated quotation
strings. The retry count is recorded; these rules do not turn failed checks into
passes. Repairs share the original whole-note soft reading budget, including
existing prose, rather than receiving a new allowance for each batch. Related
missing details should be combined without repeated setup; essential meaning is
never truncated to satisfy a word target.
`metrics.generation.coverage_ledger` records item IDs/kinds/source ranges,
statuses and matching paragraph IDs, failed batches, request count and accepted
or rejected repairs. Full item statements live in the normal request checkpoints,
not telemetry. Independent inventories are additional review calls; the complete
source still has only one **drafting** call in single mode. The old grounding
review's unresolved findings are not silently cleared by a checklist pass. When
only coverage concerns remain after a successful checklist, a final source review
can clear them only if the repaired draft actually passes. Failed or incomplete
rechecks retain the warning; grounding concerns are not waived. Optional screenshots
that fail source/time validation are skipped and recorded in diagnostics without
a reader-facing whole-note warning.

## Processing progress

Both modes publish actual drafting, grounding, source-inventory, checklist,
repair, recheck and rendering stages. Counts reflect completed batches/items;
overall percentages use approximate stage weights, not output-character targets
or elapsed-time simulation. A stage message updates even when the rounded
percentage stays the same. Long model calls retain their current percentage.
Video and podcast routes reserve the final percentage range for saving/media work.
The UI prevents backward jumps within an attempt, resets on retry, caps active
tasks below 100%, and shows elapsed time and the current step in collection and
detail views. Width transitions and a moving highlight indicate activity;
reduced-motion preferences disable those animations.

## Diagnostics and recovery

The existing processing execution store checkpoints model requests and records
`pipeline_version`, requested/actual mode, source revision, number of generation
requests, review status, paragraph source ranges and accepted/blocked screenshot
references in `metrics.generation`. No API key or full transcript is added to
these diagnostics. `implicit_fallback` is always false. Checkpoints include the
new request schema, model, endpoint, selected model options and output allowance.
Both generation evidence and complete review receipts/additions are validated
before checkpoint persistence; invalid reviews can be retried while a completed
generation is reused. Review changes are applied atomically, so malformed
additions cannot partially replace a draft. The global opening is explicitly
included in grounding checks using the reserved `overview` ID.
Successful model calls can be reused on a resumed attempt without publishing a
partial generation as a completed note.

The 133-minute comparison motivates these checks but does not establish a
causal advantage for one strategy: that comparison used different models and
prompts. Compare future strategy changes using the same model, source revision,
style, reading budget and coverage probes. Report important detail losses,
cross-part false absences, repetitions, evidence support and actual frame checks
separately from latency, word count and model usage.

## Verification

`tests/test_transcript_reading.py` covers complete-source ownership, explicit
segmentation, global answer visibility, failure/cancellation behavior, continuous
evidence, media rejection, shared public video/podcast entry points and settings
validation. `tests/test_generated_quote_roundtrip.py` checks that program-resolved
quotes and playback times survive persistence, API retrieval and exports in both
modes. The Settings UI tests cover explicit mode selection, persistence and late
refreshes. No live production summary is modified by these tests.

`tests/test_coverage_ledger.py` checks draft-blind inventory, complete source
ownership, cross-batch answers, item matching receipts, invalid cache recovery,
staged repairs, raw fallback, contradictions and duplicate/unchecked candidates.
The real Huberman source windows are retained under
`tests/fixtures/coverage_ledger/huberman.json`; mocked tests verify program
behavior, while paid live regression runs separately assess model judgments.
