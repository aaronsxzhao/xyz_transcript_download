# Reading generation

Videos and podcasts default to **full transcript, one generation**. Settings →
LLM Configuration → Summary generation also offers **Segmented generation**.
The account preference is `summary_generation_mode` (`single` or `segmented`);
engine constructors and factories accept `generation_mode` for CLI/test use.
Existing notes are not regenerated by a settings change.
Bare custom API hosts normalize to `/v1`; existing `/v1` suffixes and other
explicit API path prefixes are preserved.

## Pipeline

1. Validate/reuse the complete saved transcript. Add playback anchors only when
   the timed segments account for all source text; otherwise retain the raw
   text without inventing times. Hash the source and assign stable line IDs.
2. In `single` mode submit every source line in one generation request. Do not
   infer that a long recording needs partitioning from its duration or character
   count. A context-capacity or output-limit error fails explicitly and keeps the
   previous saved result. There is no implicit segmented fallback.
3. In `segmented` mode partition source ownership without dropping whitespace or
   unmatched tails. Each request owns its primary lines, with adjacent context
   to resolve incomplete sentences. A failed part retains its original source
   with a warning; authentication/configuration failures stop the job. Local
   extraction cannot declare a question unanswered in the whole recording.
4. Both modes produce chapters and paragraphs with **continuous source ranges**.
   Validate every endpoint, order and owned line. Preserve original quotes from
   one continuous range in each podcast evidence field, with a matching playback
   time; never splice nonadjacent excerpts into one verbatim quotation. Raw
   fallback blocks mark gaps explicitly. The model never supplies quotes or
   media timestamps. Invalid prose evidence fails generation rather than
   silently receiving manufactured references.
5. Independently review the full source in single mode, or bounded source batches
   in segmented mode, against the **global draft**,
   including later answers and already accepted missing-material additions.
   Review calls verify coverage; they do not regenerate the entire note. Add
   only missing material with valid source ranges. Incomplete receipts,
   unsupported claims or unavailable reviews produce an unverified notice;
   specifically identified unsupported paragraphs fall back to their original
   source ranges, and an unsupported opening is omitted. Their generated wording
   stays in the model checkpoint, not in the reading body.
   Model receipts are not proof of semantic completeness. Do not append another
   set of section conclusions. Exact duplicates with identical evidence are
   removed; semantic duplication is not inferred from a lexical score.
   If the provider explicitly rejects a whole-source **review** for context
   capacity (the draft adds input), partition only that review into bounded
   batches and record `review_capacity_fallback`. Generation remains a single
   whole-source request; generic failures do not trigger this review fallback.
6. Resolve screenshot time from a source ID **inside that paragraph's evidence**.
   Reject unknown/outside references, absent/out-of-range/nonchronological times
   and adjacent duplicate candidates. Keep the paragraph; skip the bad picture
   and show a provenance notice. Playback links in both video and podcast output
   also reject source times outside the known duration. Pixel correctness and visual relevance still
   require the media pipeline; transcript references alone cannot prove them.
   When the model omits the optional picture field, a chapter can use the first
   genuine timed line inside its first paragraph's evidence as its screenshot
   anchor. Diagnostics label this `chapter_source_anchor`. An explicitly invalid
   model reference is skipped rather than silently replaced with a nearby time.
7. Render the existing Markdown/summary format, extract frames through the
   existing media pipeline, then use the existing completion/version transaction.
   Cancellation, failures and retries retain the existing saved note. Raw model
   JSON is never streamed into the reader preview.

“One generation” means one whole-source drafting call. Independent coverage
reviews are additional model calls. Segmented mode additionally synthesizes one
short global opening when requested. The reading budget is shared across source
parts and remains advisory: essential steps, numerical scope and conditions take
priority over a word target.

## Diagnostics and recovery

The existing processing execution store checkpoints model requests and records
`pipeline_version`, requested/actual mode, source revision, number of generation
requests, review status, paragraph source ranges and accepted/blocked screenshot
references in `metrics.generation`. No API key or full transcript is added to
these diagnostics. `implicit_fallback` is always false. Checkpoints include the
new request schema, model, endpoint, selected model options and output allowance.
Both generation evidence and complete review receipts/additions are validated
before checkpoint persistence; invalid reviews can be retried while a completed
generation is reused. Review changes are applied atomically, so malformed
additions cannot partially replace a draft. The global opening is explicitly
included in grounding checks using the reserved `overview` ID.
Successful model calls can be reused on a resumed attempt without publishing a
partial generation as a completed note.

The 133-minute comparison motivates these checks but does not establish a
causal advantage for one strategy: that comparison used different models and
prompts. Compare future strategy changes using the same model, source revision,
style, reading budget and coverage probes. Report important detail losses,
cross-part false absences, repetitions, evidence support and actual frame checks
separately from latency, word count and model usage.

## Verification

`tests/test_transcript_reading.py` covers complete-source ownership, explicit
segmentation, global answer visibility, failure/cancellation behavior, continuous
evidence, media rejection, shared public video/podcast entry points and settings
validation. `tests/test_generated_quote_roundtrip.py` checks that program-resolved
quotes and playback times survive persistence, API retrieval and exports in both
modes. The Settings UI tests cover explicit mode selection, persistence and late
refreshes. No live production summary is modified by these tests.
