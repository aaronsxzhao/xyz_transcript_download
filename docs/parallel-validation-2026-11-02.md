# PR #211 并发验证（2026-11-02）

验证实现版本：`80975fcea654b8c4bfce18b73cba169b4114a939`。

## 真实模型：串行与并行

通过公开的 `NoteSummarizer.generate_note` 路径，使用同一份 14,147 字符合成原文、相同提示词和正常的两批清单拆分。串行对照只替换调度：清单批次依次执行，清单工作延迟到草稿完成后执行。每轮使用全新检查点，随后恢复执行一次。

模型为测试配置中的 `gpt-6-astra`，提供方为 `api.aipaibox.com`。单次对照结果：

| 指标 | 串行对照 | 并行 |
| --- | ---: | ---: |
| 耗时（包含一次无新请求的恢复） | 147.659 秒 | 73.896 秒 |
| 模型请求 | 5 | 5 |
| 最大同时请求 | 1 | 3 |
| HTTP 200 | 5 | 5 |
| 未解决覆盖项 / 失败批次 | 0 / 0 | 0 / 0 |
| 恢复新增请求 | 0 | 0 |
| 恢复命中检查点 | 5 | 5 |
| 总 token | 34,997 | 30,064 |

两轮均完成覆盖核对，恢复后的输出与首次输出一致。这个样本观察到约 50% 耗时下降；模型输出存在随机性，token 差异不代表稳定节省。

## 真实模型：同账号双 P

两个独立执行共用同一 owner，同时生成。原文结构相同，但标识分别为 ALPHA-17 / BETA-29 与 GAMMA-31 / DELTA-43，检查点与源 ID 分离。

| 指标 | P1 | P2 |
| --- | ---: | ---: |
| 首次生成耗时 | 81.819 秒 | 64.696 秒 |
| 模型请求 | 5 | 6 |
| HTTP 200 | 5 | 6 |
| 未解决覆盖项 / 失败批次 | 0 / 0 | 0 / 0 |
| 恢复新增请求 | 0 | 0 |
| 恢复命中检查点 | 5 | 6 |

两项全部完成用时 81.879 秒，同 owner 的总在途请求峰值为 3。P2 多了一次覆盖流程请求，两项均完成核对；没有真实 429 或超时。人工检查两份输出：标识没有串入另一 P，20/35 美元、至少 100 件、14 天腐蚀测试，以及 18→12 分钟、两周 80 次预约等信息保留；未测耐久、不能外推量产价格、无随机对照不能证明因果等限制也保留。

## 故障与资源隔离

新增 `tests/test_processing_parallel_stress.py` 的 7 个用例重复运行 10 次，共 70 次通过：

- 4 个任务同时执行，分别覆盖同 owner 和两个 owner。
- 分别注入一次 429、一次超时，以及无故障场景。
- 单进程请求峰值不超过 4，每个 owner 不超过 3；没有草稿串源。
- 故障后恢复成功，保存完成的检查点不再调用模型。
- 清单检查点保存后取消，后台请求结束；恢复不重复已保存清单请求。
- 所有任务结束后 owner semaphore 注册表清空。

另用真实 FFmpeg 并发抽取两份合成视频的帧：一份纯红、一份纯蓝。输出路径不同，JPEG 平均 RGB 分别约为 `(254, 0, 0)` 与 `(1, 0, 254)`，没有帧缓存串源。原有视频准备测试覆盖共享下载文件的平台分支、成功和取消后的清理顺序。

## 复现

故障测试无需真实模型：

```bash
venv/bin/python -m pytest tests/test_processing_parallel_stress.py -q
```

真实调用需要配置 `SUMMARY_TEST_API_KEY`、`SUMMARY_TEST_BASE_URL`、`SUMMARY_TEST_MODEL`，会产生模型费用。脚本最多发起 32 次请求，使用 600 秒请求准入预算与每请求最多 90 秒超时；该预算不是进程强制终止时限。

```bash
venv/bin/python scripts/validate_parallel_processing.py --output /tmp/parallel-single.json
venv/bin/python scripts/validate_parallel_processing.py --multi-part --notes-dir /tmp/parallel-notes --output /tmp/parallel-multipart.json
```

脚本不输出密钥或请求头，只记录耗时、状态、计数、摘要哈希等；可选保存的正文仅来自合成原文。

## 结论与边界

这轮没有复现乱序引用、跨 P 内容混淆、恢复重复请求或取消后的后台请求残留。实现版本的 GitHub Actions `41413784947` 已通过前端检查与测试。

加入本轮 7 项压力测试后，本地完整 Python 回归为 **1437 passed（24.05 秒）**，验证脚本也通过编译检查。真实模型结果来自上述两次独立实验，没有为获取更好的耗时反复筛选样本。

这不是实际 50 分钟视频的端到端性能基准：原文为重复的少量事实，未包含真实下载、网络转写和视觉模型耗时，也未进行长时间负载测试。覆盖模型通过不等于语义正确性的证明。当前并发上限仅在单进程生效，多 worker / 多实例会放大账号总并发；实际平台的 RPM/TPM 限流仍需部署规模下验证。本报告不代表已经部署。
